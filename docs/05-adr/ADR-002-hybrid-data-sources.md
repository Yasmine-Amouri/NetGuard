# ADR-002: Hybrid Telemetry Data Sources

- **Status:** Accepted
- **Date:** 2026-11-18

## 1. Context

NetGuard requires network telemetry to develop, train, evaluate and test its anomaly-detection capabilities.

Historical datasets provide real network observations, but they may not contain every failure scenario needed for experimentation.

Synthetic data allows us to generate controlled network conditions and reproduce specific scenarios that may be missing from historical datasets.

However, synthetic data may not accurately represent all real-world network behaviors.

## 2. Alternatives Considered

### Alternative A: Historical data only

Use recorded network measurements as the sole data source.

**Advantages:**
- Based on real network observations.
- Useful for evaluating model generalization on unseen historical data.
- Provides realistic network behavior.

**Disadvantages:**
- Limited control over the scenarios represented.
- Some anomaly types may be absent.
- Difficult to reproduce specific conditions on demand.

### Alternative B: Synthetic data only

Generate all network telemetry using a simulator.

**Advantages:**
- Full control over generated scenarios.
- Easy to reproduce anomalies.
- Allows testing extreme or unusual conditions.

**Disadvantages:**
- Simulated behavior may not represent real network conditions.
- Models may learn simulator-specific patterns.
- Good performance on synthetic data does not prove real-world generalization.

### Alternative C: Hybrid data sources

Combine historical datasets with synthetic telemetry generated by a network simulator.

**Advantages:**
- Combines real observations with controlled experiments.
- Allows testing scenarios absent from historical datasets.
- Supports reproducible experiments.

**Disadvantages:**
- Requires additional data generation and validation.
- Synthetic data may introduce unrealistic patterns.
- Requires careful separation of training and evaluation data.

## 3. Decision

We adopt a hybrid data strategy.

NetGuard will use:
- Historical network datasets for real-world observations and model evaluation.
- A synthetic network simulator for controlled experiments, reproducible anomalies and stress testing.

Both sources must produce telemetry events conforming to the same normalized event schema.

## 4. Consequences

The platform can be tested under a wider variety of network conditions.

However, results obtained using synthetic data must not be presented as proof of real-world model performance.

Model evaluation will prioritize unseen historical observations, with clear separation between training and evaluation data.
